État des lieux — Cahier des charges Approvisionnement & Supply Chain
Mise à jour : 2026-07-27 (revue complète contre le texte intégral du CDC, 19 sections)

Toutes les sections sont couvertes, à l'exception du §19 (architecture
microservices), volontairement laissée de côté : le CDC demande microservices,
multi-tenant, Kubernetes, RabbitMQ, Elasticsearch pour 50 000 agences / 1M
produits / 1M commandes par mois. AfriGes est un monolithe Next.js + Prisma +
PostgreSQL (Vercel), single-tenant, pour une entreprise togolaise — ce n'est
pas implémenté littéralement à ce stade. À reconsidérer seulement si demandé
explicitement.

Build : npm run build vert (622/622 pages, 0 erreur TypeScript).

Simplifications assumées (documentées dans le code, pas des manques cachés)

- Signature électronique du Bon de Commande : tampon interne (utilisateur +
  horodatage), pas de prestataire de signature qualifiée (DocuSign etc.).
- Suivi importations "temps réel" : journal de checkpoints saisis
  manuellement par l'agent appro, pas de flux GPS/EDI transporteur/douane
  automatique.
- Finances (factures fournisseurs à payer, prévisions de trésorerie) :
  signalées "non disponible" sur le dashboard plutôt que simulées — nécessi-
  teraient un module comptabilité fournisseurs/trésorerie qui n'existe pas.
- §16 BI/IA : projection statistique explicable (moyenne mobile, delta de
  tendance), pas un modèle prédictif entraîné — voir lib/previsionStock.ts.
- Rotation des stocks : ratio sorties 6 mois / valeur stock ACTUEL (pas de
  snapshot d'inventaire historique pour une vraie moyenne de période).
- Blocage/consignation de stock (§11) : API fonctionnelle (bloquer/débloquer/
  consigner/déconsigner), pas encore d'écran dédié — utilisable via
  /api/admin/stock/[id] (PUT, blocageAction).
- 2FA (§18) : non implémentée — décision d'architecture d'authentification
  globale à l'application, pas spécifique au module appro ; à traiter
  séparément si voulu.
