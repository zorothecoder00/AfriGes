AFRISIME SARL — AfriGes
GUIDE D'UTILISATION DES DOCUMENTS DIGITALISÉS
==============================================

À PROPOS DE CE DOCUMENT
------------------------
Ce fichier contenait à l'origine le Cahier des Charges de digitalisation
(spécifications, Partie A §3.1-3.6 + Partie B §5.1-5.10). Ce CDC a été
intégralement implémenté et vérifié (audit final, septembre 2026). Il est
remplacé ici par un GUIDE OPÉRATIONNEL : comment accéder à chaque document
dans AfriGes, comment le remplir, et comment le faire progresser dans son
circuit de validation. La numérotation §X.Y est conservée pour rester
traçable par rapport au CDC d'origine (consultable dans l'historique git si
besoin : `git log -- cdcdigitalisation.txt`).

Tous les documents s'impriment de la même façon : PDF généré côté serveur
(moteur Chromium headless, lib/pdf.ts), accessible via un lien/bouton
"Imprimer" qui ouvre `GET /api/.../[id]/pdf` dans un nouvel onglet. Chaque
PDF embarque un QR sécurisé par empreinte cryptographique (hash HMAC,
lib/documentQr.ts) qui permet de retrouver le document via `/q/[code]/[id]`.

Connexion : chaque gestionnaire se connecte avec son compte AfriGes
(identifiant/mot de passe ou Google selon configuration). L'accès à chaque
page ci-dessous est automatiquement filtré par rôle — un agent ne voit que
ses propres documents, un service ne voit que ceux qui lui sont adressés.
Un Admin/Super Admin a accès à tout, en plus des rôles cités par document.


PARTIE A — LES 6 DOCUMENTS PRIORITAIRES (§3.1 à §3.6)
======================================================
Ce sont les seuls documents dotés d'un QR code "Instance" sécurisé par
empreinte cryptographique (hash HMAC) au sens strict du CDC §4 — chaque
document imprimé porte un QR qui permet de le retrouver et de vérifier son
authenticité via `/q/[code]/[id]`.

§3.1 — BORDEREAU DE REMISE DE FONDS
------------------------------------
Objectif : un collecteur/agent terrain remet à la trésorerie les fonds
collectés sur le terrain (cotisations, remboursements, ventes).

Accéder :
  - Créer : /dashboard/user/agentsTerrain/bordereaux-remise (Agent terrain)
  - Traiter/clôturer : /dashboard/user/comptables/tresorerie/bordereaux-remise
    (Comptable / Chef Comptable / Trésorier)
  - Admin : page native dédiée /dashboard/admin/bordereaux-remise (création,
    traitement, visa CGT, clôture — vue globale, pas de scope PDV)

Remplir (à la création) :
  - Point de vente (pré-rempli selon votre affectation)
  - Cotisations espèces, cotisations mobile money (+ référence de
    transaction si > 0), remboursements, ventes, vente de carnet, frais de
    livraison, montant viré/déposé (+ référence si > 0)
  - Billetage : nombre de billets/pièces par dénomination (grille de 10
    lignes) — le total est calculé automatiquement
  - Motif de l'écart : obligatoire si le billetage ne correspond pas au
    total espèces attendu

Gérer (workflow) :
  SOUMIS → (le trésorier compare au billetage déclaré) → VALIDE ou
  ECART_SIGNALE → (si montant total > seuil paramétré) visa du Président
  CGT obligatoire → CLOTURE (référence de dépôt bancaire obligatoire —
  déclenche désormais automatiquement l'écriture comptable Dr Banque /
  Cr Caisse).
  Actions disponibles : Traiter (trésorier), Viser CGT (Direction),
  Clôturer (trésorier).

Imprimer : PDF serveur — bouton dédié sur la page, ou
  GET /api/tresorerie/bordereaux-remise/[id]/pdf


§3.2 — BON DE COMMANDE CLIENT
-------------------------------
Objectif : un agent terrain prend commande auprès d'un client.

Accéder :
  - Créer/suivre : /dashboard/user/agentsTerrain/commandes-client
    (Agent terrain, Commercial)
  - Superviser : /dashboard/user/responsablesVenteCredit/commandes-client
    (Responsable Vente Crédit)
  - Admin : page native dédiée /dashboard/admin/commandes-client (création,
    visa/rejet, annulation, clôture, liens Bon de livraison/Bon de réception)

Remplir :
  - Client (recherche par téléphone pour éviter les doublons)
  - Type de client (Particulier / Revendeur — bascule sur la grille
    tarifaire B2B), mode de règlement (Comptant / Mobile Money / À crédit)
  - Lignes produits (produit, quantité, remise % éventuelle — validation
    du Responsable Commercial requise au-delà d'un seuil)
  - Date/lieu de livraison souhaités
  - Signature électronique du client (tactile ou code SMS) — obligatoire

Gérer (workflow) :
  Soumis → Visé (si remise/crédit) ou rejeté → une fois validée, un Bon de
  Sortie de Marchandises est généré automatiquement → Clôturé une fois
  livrée. Actions : Viser, Rejeter, Annuler, Clôturer.

Imprimer : GET /api/ventes/commandes-client/[id]/pdf


§3.3 — BON DE COMMANDE FOURNISSEUR
------------------------------------
Objectif : commande passée par AfriSime à un fournisseur.

Accéder : /dashboard/user/logistiquesApprovisionnements/bons-commande
  (Agent Logistique/Approvisionnement) — Admin : page native dédiée
  /dashboard/admin/bons-commande-fournisseur (mêmes API, gestion complète
  sans passer par une page "user")

Remplir :
  - Fournisseur, point de vente/dépôt destinataire, date de livraison
    prévue, devise
  - Lien optionnel vers une Demande de cotation (RFQ) déjà comparée
  - Lignes (produit, quantité, prix unitaire)

Gérer (workflow) :
  DRAFT → PENDING_APPROVAL → APPROVED → SENT → ACKNOWLEDGED (fournisseur)
  → PARTIALLY_DELIVERED → COMPLETED (ou CANCELLED à tout moment avant
  envoi). Actions : Approuver, Signer, Viser CGT (montant élevé),
  Enregistrer un paiement ; boutons dédiés Envoyer / Livraison / Importation.

Imprimer : GET /api/logistique/bons-commande/[id]/pdf


§3.4 — BON DE SORTIE DE MARCHANDISES
---------------------------------------
Objectif : constate et exécute la sortie physique de stock.

Accéder : /dashboard/user/magasiniers, onglet "Sorties" (Magasinier) —
  Admin : page native dédiée /dashboard/admin/stock/sorties (le PDV
  concerné se choisit explicitement dans le formulaire, l'admin n'a pas
  d'affectation propre)

Remplir :
  - Point de vente/dépôt (votre affectation)
  - Motif : Livraison client (généré automatiquement depuis une commande
    validée) / Transfert de stock / Consommation interne / Perte / Casse /
    Don / Autre
  - Lignes (produit, quantité demandée) — la quantité effectivement sortie
    peut être ajustée en cas de rupture partielle, avec commentaire

Gérer (workflow) :
  BROUILLON → VALIDE (le magasinier atteste la disponibilité et exécute la
  sortie en une fois) ou ANNULE. La validation déduit le stock et génère
  automatiquement le Bon de Livraison (+ Bon de Réception si rattaché à
  une commande client).

Imprimer : GET /api/magasinier/bons-sortie/[id]/pdf


§3.5 — BON DE RÉCEPTION (client)
------------------------------------
Objectif : le client atteste avoir reçu sa commande.

Accéder :
  - Côté interne : consultable depuis le détail de la Commande Client liée
    (/dashboard/user/agentsTerrain/commandes-client) — pas de page dédiée,
    ce n'est pas nécessaire puisqu'il est rattaché à la commande.
  - Côté client (SANS COMPTE) : lien envoyé par SMS vers
    /livraison/[jeton] — jeton opaque à usage unique, aucune connexion
    requise (conforme CDC §2.1 "lien de confirmation sans compte complet").

Remplir (par le client, sur le lien reçu) :
  - Quantité livrée par ligne (écart calculé automatiquement)
  - État de la marchandise (Conforme / Non conforme + réserve obligatoire
    si non conforme, avec photo possible)
  - Signature électronique tactile (ou confirmation SMS)

Gérer (workflow) :
  EN_ATTENTE_SIGNATURE → signé (clôture la commande) ; une réserve ou un
  écart déclenche une notification automatique à l'agent terrain et au
  Service Commercial (pour ouvrir, si besoin, une réclamation — §5.8).

Imprimer : GET /api/bons-reception/[id]/pdf


§3.6 — FICHE DE DÉCAISSEMENT
--------------------------------
Objectif : toute sortie de fonds (achat, avance, frais...).

Accéder : /dashboard/user/decaissements (tout gestionnaire connecté peut
  en créer une — namespace neutre ; approbation/exécution par
  hiérarchie/Comptable) — Admin : page native dédiée
  /dashboard/admin/decaissements

Remplir :
  - Bénéficiaire, motif (10 caractères minimum), type de dépense (Achat
    marchandises / Fournitures / Paiement fournisseur / Avance de caisse /
    Frais de fonctionnement / Transport / Autres)
  - Montant demandé, pièces justificatives (obligatoires pour Achat de
    marchandises et Paiement fournisseur)
  - Rattachement à un Bon de Commande Fournisseur si applicable

Gérer (workflow) :
  SOUMISE → APPROUVEE (niveau 1, puis niveau 2 si seuil dépassé) → PAYEE
  (Comptable exécute, génère l'écriture comptable) — ou REJETEE.
  Actions : Approuver N1, Approuver N2, Rejeter, Exécuter.

Imprimer : GET /api/decaissements/[id]/pdf

§5.2 — DOCUMENTS DE VENTE
---------------------------

DEVIS / PROFORMA
  Accéder : /dashboard/user/agentsTerrain/devis-proforma
    (Agent terrain, Commercial) — Admin : page native dédiée
    /dashboard/admin/devis-proforma
  Remplir : type (Devis ou Proforma), client, date de validité (15 jours
    par défaut), conditions (texte libre saisi par l'agent — pas de
    format imposé), lignes produits (quantité, remise % éventuelle), notes
  Gérer : Envoyer, Convertir un Devis en Proforma, Annuler
  Imprimer : GET /api/ventes/devis-proforma/[id]/pdf

BON DE PRÉPARATION
  Généré automatiquement à la validation d'une Commande Client ; le
  magasinier le traite depuis /dashboard/user/magasiniers en prélevant les
  articles puis en le marquant "prêt" (répercute sur le Bon de Sortie lié).
  Document de travail interne, pas d'impression dédiée.

BON DE LIVRAISON
  Généré automatiquement à la validation du Bon de Sortie, visible dans
  /dashboard/user/magasiniers (Admin : /dashboard/admin/stock/sorties,
  lien direct sous le bon de sortie d'origine). Pas de statut/workflow
  propre (figé une fois émis). Imprimer : GET /api/bons-livraison/[id]/pdf

FACTURE / FACTURE À CRÉDIT / FACTURE D'AVOIR
  Générée automatiquement à chaque vente (pas de page de création
  séparée) ; consultable via la fenêtre "Facture" présente sur : ventes
  admin, crédits admin, packs admin, agentsTerrain, agentsTerrain/credits,
  caissiers, responsablesPointDeVente, responsablesVenteCredit et
  responsablesVenteCredit/credits.
  Facture d'avoir (correction après retour/réclamation) : réservée au
  Comptable, via la fiche client → onglet Avoirs (peut désormais être
  rattachée à une réclamation, cf. §5.8).

REÇU DE PAIEMENT
  Pas de document séparé : la facture comptant fait foi de reçu de
  paiement (choix assumé, évite un doublon).


§5.3 — DOCUMENTS D'ACHAT ET FOURNISSEURS
-------------------------------------------

DEMANDE D'ACHAT INTERNE
  Accéder : /dashboard/user/logistiquesApprovisionnements/demandes-achat
    (Agent Logistique/Approvisionnement)
  Remplir : motif, lignes (produit, quantité)
  Gérer : Viser (RPV / Chef d'agence / Direction selon seuil), Rejeter,
    Annuler, Clôturer

DEMANDE DE COTATION (RFQ) + TABLEAU COMPARATIF
  Accéder : /dashboard/user/logistiquesApprovisionnements/rfq
  Remplir : produit, quantité, point de vente, fournisseurs sollicités
    (au moins un), date limite de réponse, lien optionnel vers une ligne
    de demande d'achat
  Gérer : BROUILLON → ENVOYEE → REPONSES_RECUES (saisie des cotations
    reçues) → comparatif → "Retenir" un fournisseur → CLOTUREE

BON DE COMMANDE FOURNISSEUR ET CONFIRMATION
  Voir §3.3 ci-dessus (Partie A) — peut être initié depuis une RFQ retenue.

RÉCEPTION FOURNISSEUR + FICHE DE CONTRÔLE
  Accéder : /dashboard/user/logistiquesApprovisionnements (hub),
    également visible depuis /dashboard/user/magasiniers et
    /dashboard/gestionnaire/logistique
  Remplir : type de réception, point de vente, fournisseur, date
    prévisionnelle, lignes, mode de règlement
  Gérer : BROUILLON → EN_COURS → RECU → VALIDE (ou ANNULE) — la validation
    contrôle conformité qualité/quantité et met à jour le stock

FACTURE FOURNISSEUR
  Accéder : /dashboard/user/comptables/factures-achat (Comptable) — Admin :
  page native dédiée /dashboard/admin/factures-fournisseur
  Remplir : fournisseur (recherche), n° de facture, date, montant TTC,
    réception liée (optionnel)
  Gérer : NON_RAPPROCHEE → RAPPROCHEE (bouton "Rapprocher", éventuellement
    en la liant à une réception). Une facture non rapprochée déclenche une
    alerte comptable automatique.

AVOIR FOURNISSEUR, ORDRE DE PAIEMENT, PREUVE DE PAIEMENT
  Avoir fournisseur : fiche fournisseur, onglet dédié
    (/dashboard/user/comptables/auxiliaire/fournisseurs/[id]) — Comptable
  Ordre/preuve de paiement : couverts par la Fiche de Décaissement (§3.6),
    rattachable au fournisseur — pas de document séparé (réutilisation
    assumée du circuit de décaissement existant)

FICHE D'ÉVALUATION FOURNISSEUR
  Pas de document séparé : la note globale du fournisseur (visible sur sa
  fiche) est recalculée automatiquement à partir des réceptions.


§5.4 — DOCUMENTS SPÉCIFIQUES À LA VENTE À CRÉDIT
----------------------------------------------------

DEMANDE DE CRÉDIT / CONTRAT DE CRÉDIT
  Accéder : /dashboard/user/responsablesVenteCredit/credits (RVC),
    /dashboard/admin/credits (Admin)
  Remplir : client, produits, montant, durée (Quinzaine = 16 échéances ou
    Trentaine = 31 échéances), frais de dossier, assurance, garantie
    (nom/téléphone/adresse/type/valeur du garant)
  Gérer : EN_ATTENTE_VALIDATION → VALIDE → ACTIF (remboursement en cours)
    → EN_RETARD si échéance impayée → SOLDE (intégralement remboursé)

FICHE D'IDENTIFICATION / ÉVALUATION CLIENT
  Fiche client standard (codeClient, coordonnées) + historique de score
  (ClientScoreHistorique) consultés depuis la fiche client.

CARNET DE CRÉDIT DIGITAL / ÉCHÉANCIER / RELEVÉ DE COMPTE
  Accéder (sans compte, lien envoyé au client) : /suivi/[reference] — vue
    complète : progression du remboursement, calendrier jour par jour,
    montants payés/restants, statut de chaque échéance
  Accéder (interne) : détail du crédit dans /dashboard/admin/credits ou
    /dashboard/user/responsablesVenteCredit/credits

REÇU DE REMBOURSEMENT
  Généré depuis le détail du crédit (bouton imprimante sur chaque
  remboursement enregistré) : GET /api/admin/credits/[id]/remboursements/
  [rembId]/pdf

AVIS D'ÉCHÉANCE / AVIS DE RETARD
  Généré depuis le détail du crédit, bouton "Avis" sur l'échéancier :
  GET /api/admin/credits/[id]/avis-echeance/pdf (calcul automatique —
  échéances impayées et échues → Avis de retard, sinon prochaine échéance
  → Avis d'échéance), en plus de la notification SMS/WhatsApp automatique.

MISE EN DEMEURE / FICHE DE VISITE DE RECOUVREMENT / RAPPORT DE
RECOUVREMENT / FICHE DE VISITE
  Accéder : détail du crédit (/dashboard/admin/credits ou
    /dashboard/user/responsablesVenteCredit/credits) → panneau
    "Recouvrement" (RVC, Admin)
  Remplir : type d'action (Appel téléphonique / Visite terrain / Mise en
    demeure / Accord d'échéancier / Saisie de garantie / Note interne) ;
    pour une visite : lieu (obligatoire) et personne rencontrée ; pour une
    mise en demeure : délai de régularisation (8 jours par défaut)
  Imprimer : GET /api/admin/credits/[id]/recouvrement/[actionId]/pdf — la
    Mise en demeure et la Fiche de visite s'ouvrent automatiquement dans
    un nouvel onglet à la création de l'action.

ÉTAT DES IMPAYÉS
  Vue consolidée disponible dans le Contrôle commercial, voir §5.9
  ci-dessous (onglet "Impayés").

ATTESTATION DE SOLDE / QUITTANCE FINALE
  Accéder : détail du crédit → bouton "Attestation de solde / quittance
    finale" (visible uniquement une fois le crédit intégralement soldé)
  Imprimer : GET /api/admin/credits/[id]/attestation-solde/pdf


§5.5 — DOCUMENTS SPÉCIFIQUES AU DÉPÔT-VENTE
------------------------------------------------
Tout le module est regroupé sur une seule page :
  /dashboard/user/logistiquesApprovisionnements/depot-vente
  (Agent Logistique/Approvisionnement) — Admin : page native dédiée
  /dashboard/admin/depot-vente (3 onglets : conventions, dépôts, état &
  règlements)

CONVENTION DE DÉPÔT-VENTE
  Remplir : fournisseur, taux de commission (%), date de fin éventuelle,
    conditions. Statuts : ACTIVE / SUSPENDUE / TERMINEE

FICHE DE DÉPÔT DE MARCHANDISES / BON D'ENTRÉE EN DÉPÔT
  Un seul document couvre les deux (fusion assumée) : convention liée,
  point de vente, lignes de produits déposés.
  Statuts : BROUILLON → EN_STOCK → CLOTURE

ÉTAT DU STOCK EN DÉPÔT / ÉTAT DES VENTES / ÉTAT DES INVENDUS / RAPPORT
PÉRIODIQUE
  Un seul écran agrégé (au lieu de 4 documents séparés) : sur la page,
  sélectionner la convention pour voir stock restant, ventes réalisées et
  invendus sur la période.

BON DE SORTIE / REPRISE DES INVENDUS
  Depuis l'état des invendus, action de reprise disponible pour organiser
  le retour au fournisseur.

DEMANDE DE RÈGLEMENT FOURNISSEUR
  Remplir : convention concernée — le montant dû est calculé
    automatiquement depuis les ventes réalisées. Statuts : BROUILLON →
    SOUMIS → REGLE (passe alors par le circuit Fiche de Décaissement, §3.6)

REÇU DE RÈGLEMENT / RELEVÉ FOURNISSEUR (DÉPÔT-VENTE)
  Pas de document séparé : le PDF de la Fiche de Décaissement associée
  sert de reçu ; le relevé général du fournisseur (grand livre auxiliaire)
  est visible depuis sa fiche comptable.


§5.6 — DOCUMENTS COMMERCIAUX REVENDEURS / B2B
--------------------------------------------------
Accéder :
  - Gestion des comptes (Admin, RVC) : /dashboard/admin/revendeurs
  - Espace self-service du revendeur : /dashboard/user/revendeurs

FICHE D'OUVERTURE DE COMPTE / CARTE CLIENT PROFESSIONNEL
  Sur /dashboard/admin/revendeurs, bouton "Ouvrir un compte" : choisir un
  utilisateur ayant le rôle REVENDEUR, puis renseigner raison sociale, nom
  commercial, NIF, RCCM, adresse, ville, contact, point de vente rattaché,
  conditions particulières. Statuts : ACTIF / SUSPENDU / RESILIÉ.
  Imprimer (variantes ouverture/carte/convention/attestation, sélection par
  bouton) : GET /api/admin/revendeurs/[id]/pdf?variante=OUVERTURE|CARTE|
  CONVENTION|ATTESTATION (self-service revendeur : /api/revendeur/profil/pdf)

GRILLE TARIFAIRE REVENDEUR
  Réutilise le type de prix "GROS" du Catalogue Produits — visible/gérée
  depuis la fiche produit (module Catalogue), pas une page séparée.
  Imprimable via ?variante=GRILLE sur la route ci-dessus.

BON DE COMMANDE REVENDEUR
  Créé par le revendeur depuis /dashboard/user/revendeurs (ou par
  l'Admin/RVC pour son compte) : produits, quantités — la grille GROS
  s'applique automatiquement.
  Statuts : BROUILLON → CONFIRMEE → LIVREE → FACTUREE (ou ANNULEE)
  Imprimer : GET /api/admin/revendeurs/[id]/commandes/[commandeId]/pdf
  (self-service : /api/revendeur/commandes/[id]/pdf)

FACTURE REVENDEUR / BON DE LIVRAISON REVENDEUR
  Générés automatiquement à la confirmation/livraison de la commande.
  Imprimer : .../commandes/[commandeId]/facture/pdf et
  .../commandes/[commandeId]/bon-livraison/pdf (mêmes routes admin/RVC et
  self-service que ci-dessus)

RELEVÉ DE COMPTE REVENDEUR / ÉTAT DES ACHATS
  Depuis la fiche du revendeur (/dashboard/admin/revendeurs, détail) :
  GET /api/admin/revendeurs/[id]/releve/pdf — historique des commandes/
  factures (self-service : /api/revendeur/releve/pdf).

CONDITIONS PARTICULIÈRES ACCORDÉES
  Champ libre dans la fiche d'ouverture de compte (voir plus haut).


§5.7 — DOCUMENTS DE LIVRAISON ET LOGISTIQUE (TOURNÉES)
------------------------------------------------------------
Accéder : /dashboard/user/logistiquesApprovisionnements/tournees
  (Agent Logistique/Approvisionnement, Magasinier — pas de rôle "livreur"
  séparé : les tournées sont pilotées depuis le back-office) — Admin : page
  native dédiée /dashboard/admin/tournees

FICHE DE TOURNÉE / FICHE DE MISSION DU LIVREUR / FICHE DE CHARGEMENT /
BORDEREAU DE LIVRAISON
  Un seul modèle (TourneeLivraison) avec plusieurs variantes d'impression.
  Créer une tournée : point de vente, livreur (utilisateur), date, arrêts
  (client + adresse, ou rattachés à un Bon de Livraison existant).
  Statuts : PLANIFIEE → EN_COURS → TERMINEE (ou ANNULEE)
  Imprimer : GET /api/logistique/tournees/[id]/pdf?variante=MISSION|
  CHARGEMENT|BORDEREAU (3 boutons sur le détail de la tournée)

FICHE DE LIVRAISON NON EFFECTUÉE / FICHE D'INCIDENT LIVRAISON / FICHE DE
RETOUR MARCHANDISES (post-livraison)
  Pour chaque arrêt de la tournée : renseigner le résultat (Effectué / Non
  effectué + motif / Incident + description / Retour de marchandise +
  lignes retournées et motif).
  Statuts de l'arrêt : PLANIFIE → EFFECTUE / NON_EFFECTUE / INCIDENT
  Imprimer : GET /api/logistique/tournees/[id]/arrets/[arretId]/pdf (le
  titre s'adapte automatiquement au statut constaté)

RAPPORT DE LIVRAISON
  Onglet "Rapport" de la page tournées : agrégation des tournées/arrêts
  sur une période (pas un document imprimable séparé, une vue de synthèse).


§5.8 — DOCUMENTS DE RETOUR ET RÉCLAMATION
------------------------------------------------
Accéder :
  - Enregistrement et suivi : /dashboard/admin/reclamations
    (Admin, Responsable Point de Vente, Chef d'agence)
  - Traitement physique des retours : /dashboard/user/magasiniers/retours-client
    (Magasinier) — Admin : mêmes actions (Réceptionner/Valider/Rejeter)
    directement intégrées dans /dashboard/admin/reclamations, détail de la
    réclamation
  - Traitement des remplacements : /dashboard/user/magasiniers/remplacements
    (Magasinier) — Admin : mêmes actions (Approuver/Livrer/Rejeter)
    directement intégrées dans /dashboard/admin/reclamations, détail de la
    réclamation

FORMULAIRE DE RÉCLAMATION CLIENT
  Sur /dashboard/admin/reclamations, bouton "Nouvelle réclamation" :
  rechercher le client, choisir le type (Produit défectueux / Livraison
  non conforme / Erreur de facturation / Retard de livraison / Qualité de
  service / Autre), objet, description, référence de la vente/facture/
  crédit d'origine (facultatif).
  Imprimer : GET /api/admin/reclamations/[id]/pdf

FICHE DE TRAITEMENT DE RÉCLAMATION / FICHE DE CLÔTURE
  Depuis le détail de la réclamation : ajouter des actions au journal de
  traitement (prise en charge, investigation, décision, note interne),
  prendre en charge, rejeter (motif obligatoire) ou clôturer (résumé de
  clôture obligatoire, uniquement depuis le statut Résolue).
  Statuts : ENREGISTREE → EN_TRAITEMENT → RESOLUE → CLOTUREE (ou REJETEE)
  Imprimer : GET /api/admin/reclamations/[id]/traitement/pdf (devient
  automatiquement "Fiche de clôture" une fois le statut Clôturée atteint).

FICHE DE RETOUR MARCHANDISE / BON DE RETOUR
  Depuis le détail d'une réclamation, bouton "Fiche de retour" : choisir
  le(s) produit(s), quantité, état constaté. Le magasinier réceptionne
  puis valide sur /dashboard/user/magasiniers/retours-client (la
  validation recrédite automatiquement le stock).
  Statuts : DECLARE → RECEPTIONNE → VALIDE (devient alors "Bon de retour")
  Imprimer : GET /api/admin/reclamations/[id]/retours/[retourId]/pdf
  (variante selon le statut ; accessible au Service Commercial comme au
  Magasinier).

BON DE REMPLACEMENT
  Depuis le détail d'une réclamation, bouton "Bon de remplacement" :
  produit d'origine (défectueux), produit de remplacement, quantité. Le
  magasinier approuve puis livre sur
  /dashboard/user/magasiniers/remplacements (la livraison décrémente
  automatiquement le stock du produit de remplacement).
  Statuts : DEMANDE → APPROUVE → LIVRE
  Imprimer : GET /api/admin/reclamations/[id]/remplacements/
  [remplacementId]/pdf

RAPPORT D'INCIDENT
  Depuis le détail d'une réclamation (bouton "Déclarer un incident") ou de
  façon autonome via l'API : lieu, type (Livraison / Produit / Comportement
  client / Comportement agent / Autre), description, personnes impliquées,
  actions correctives.
  Imprimer : GET /api/admin/reclamations/incidents/[incidentId]/pdf

AVOIR CLIENT (dans ce circuit)
  Depuis le détail d'une réclamation, bouton "Émettre un avoir" (action
  réservée au Comptable/Admin — un RPV/Chef d'agence recevra un refus
  d'accès, c'est voulu, séparation des tâches) : montant, motif. L'avoir
  est automatiquement rattaché à la réclamation et fait passer son statut
  à Résolue.


§5.9 — CONTRÔLE COMMERCIAL & REPORTING
-------------------------------------------
Accéder : /dashboard/admin/controle-commercial (Admin/Super Admin
  uniquement — module de pilotage, pas de saisie)

Ce n'est pas un document à remplir mais un tableau de bord à consulter :
  1. Choisir la période (Jour / Semaine / Mois) et une date de référence
  2. Filtrer, si besoin, sur une agence (point de vente) précise
  3. Naviguer entre les onglets :
     - Tableau de bord : vue consolidée (CA, panier moyen, encaissé,
       crédit, impayés, recouvrement, retours, réclamations)
     - Ventes : chiffre d'affaires et détail jour par jour
     - Par agent / Par produit / Par agence : classements
     - Ventes à crédit : volume et encours des crédits ouverts
     - Encaissements : répartition par mode de paiement + remboursements
       crédit encaissés
     - Impayés : liste des échéances en retard par client, avec pénalités
     - Recouvrement : actions de recouvrement par type et par statut
     - Retours / Réclamations : volumes par statut
     - Performances : taux de crédit, taux de retour, taux de réclamation

Tout se rafraîchit automatiquement selon les filtres choisis ; aucune
action de validation n'est nécessaire ici, c'est un outil de lecture.


CENTRE DE COMMANDEMENT (point d'entrée unique, hors numérotation CDC)
=============================================================
Accéder : /dashboard/admin/centre-commandement (Admin/Super Admin ; RPV et
  Chef d'agence y ont aussi accès, scopé à leur(s) point(s) de vente).

Ajouté pour centraliser l'accès à tous les documents ci-dessus sans avoir à
mémoriser une page par module :
  1. Recherche globale : tapez une référence (BRF-2026-..., REC-2026-...),
     un nom ou un numéro de téléphone client — le moteur interroge en
     parallèle les 17 familles de documents principales (§3.1 à §5.8) et
     renvoie les correspondances avec un lien direct "Imprimer" (PDF) et un
     lien vers la fiche complète. API : GET
     /api/centre-commandement/recherche?q=...
  2. Annuaire par module : liste de tous les documents du CDC digitalisation
     avec leur description et un lien vers la page où les créer/gérer,
     classée par section (§3.x, §5.x) — utile pour découvrir un circuit
     qu'on ne pratique pas au quotidien. Pour un viewer Admin, ce lien pointe
     vers la page admin native quand elle existe (voir ci-dessous), jamais
     vers une page "user" en écriture.
Le contrôle commercial (§5.9) et les réclamations (§5.8) restent en outre
accessibles directement depuis la barre latérale Admin ("Pilotage &
documents") — ils n'avaient auparavant aucun lien de navigation direct.

PAGES ADMIN NATIVES (créer/gérer/imprimer sans passer par une page "user") :
  - Bordereau de remise de fonds (§3.1) : /dashboard/admin/bordereaux-remise
  - Bon de commande client (§3.2) : /dashboard/admin/commandes-client
  - Bon de commande fournisseur (§3.3) : /dashboard/admin/bons-commande-fournisseur
  - Bons de sortie de marchandises (§3.4) : /dashboard/admin/stock/sorties
  - Fiche de décaissement (§3.6) : /dashboard/admin/decaissements
  - Devis / Proforma (§5.2) : /dashboard/admin/devis-proforma
  - Demandes d'achat interne (§5.3) : /dashboard/admin/demandes-achat
  - RFQ + tableau comparatif (§5.3) : /dashboard/admin/rfq
  - Réception fournisseur (§5.3) : /dashboard/admin/approvisionnements
    (création directe + validée, ou approbation/réception physique d'une
    réception soumise par la logistique)
  - Factures fournisseurs (§5.3) : /dashboard/admin/factures-fournisseur
  - Dépôt-vente (§5.5) : /dashboard/admin/depot-vente
  - Tournées de livraison (§5.7) : /dashboard/admin/tournees
  - Retours/remplacements (§5.8) : actions intégrées à /dashboard/admin/reclamations
Bon de réception (§3.5) et Bon de livraison (§5.2) restent des documents
générés automatiquement sans workflow propre : consultables/imprimables
depuis, respectivement, /dashboard/admin/commandes-client et
/dashboard/admin/stock/sorties (pas de page dédiée, ce n'est pas
nécessaire). Restent sur leur page "user" d'origine (déjà ouverte en
plein droit à l'admin par proxy.ts, hors mécanisme de lecture seule
"viewAs") : Fournisseurs, MRP et Tableau de bord Approvisionnement — des
outils de support, pas des documents du catalogue CDC.


RÉCAPITULATIF DES RÔLES ET DE LEURS DOCUMENTS PRINCIPAUX
=============================================================
  Agent terrain         : Bordereau de remise, Commande client, Devis/Proforma
  RPV / Chef d'agence    : réclamations, visas, supervision agence
  Caissier               : ventes comptant, factures
  Magasinier             : sorties de stock, réceptions, retours, remplacements
  Agent Logistique/Appro : achats, RFQ, dépôt-vente, tournées de livraison
  Comptable              : décaissements, avoirs, factures fournisseur, écritures
  RVC (Vente Crédit)     : crédits, recouvrement
  Revendeur (B2B)        : ses propres commandes, factures, relevé
  Admin / Super Admin    : accès total + Contrôle commercial & reporting
