 Voilà. Ce que tu dois remplir obligatoirement pour activer les alertes :

  Pour le SMS (Africa's Talking — recommandé pour l'Afrique de l'Ouest) :
  1. SMS_ENABLED=true
  2. AT_API_KEY → clé API depuis https://africastalking.com
  3. AT_USERNAME → ton nom d'utilisateur AT (souvent le nom de ton app)

  Pour WhatsApp (Twilio — plus simple à démarrer) :
   Étapes réelles pour activer les notifications WhatsApp

  1. Compte Twilio — crée un compte sur https://console.twilio.com, récupère
  Account SID et Auth Token (page d'accueil de la console).
  2. Numéro WhatsApp :
    - Pour tester tout de suite : active le WhatsApp Sandbox de Twilio (gratuit,
  numéro +14155238886). Limite importante : chaque destinataire (toi, tes
  admins, tes agents terrain) doit d'abord envoyer le code d'activation ("join
  xxx-xxx") depuis son propre WhatsApp vers ce numéro sandbox — sinon Twilio
  refuse d'envoyer. Ça marche pour valider que le système fonctionne, mais pas
  utilisable en prod avec de vrais clients (ils ne feront jamais cette manip).
    - Pour la vraie prod : il faut demander un numéro WhatsApp Business Sender
  via Twilio (vérification d'entreprise + approbation Meta, ça prend quelques
  jours). Comme les rappels de retard sont des messages initiés par toi (pas une
  réponse à un message du client), Meta exige aussi un template de message
  pré-approuvé pour ce type d'envoi.
  3. Variables d'environnement (Vercel + ton .env local) :
  WA_ENABLED=true
  TWILIO_ACCOUNT_SID=...
  TWILIO_AUTH_TOKEN=...
  TWILIO_WA_FROM=+14155238886   # ou ton numéro approuvé en prod
  DEFAULT_PHONE_PREFIX=228      # 228 Togo, 229 Bénin, 225 CIV
  4. Test manuel avant de compter sur le cron : appelle GET /api/cron/alertes
  toi-même (navigateur ou curl) une fois les variables posées, et regarde les
  logs Vercel pour les lignes [WA] ... (erreurs explicites si un numéro ou une
  variable manque).
  5. Vérifie que les numéros des admins/agents terrain (ceux qui reçoivent
  l'alerte aujourd'hui, pas le client) sont bien enregistrés dans
  Gestionnaire/User et ont rejoint le sandbox si tu testes avec le sandbox.
  6. Une fois validé, le cron Vercel (déjà programmé à 08h00) prend le relais
  automatiquement — rien d'autre à déployer.

Modifier les identifiants — deux cas différents

  Ton propre compte (admin) :
  Page Paramètres (/dashboard/admin/parametres, via
  components/settings/AccountSettings.tsx) → tu peux changer ton email, ta
  photo, tes coordonnées, et ton mot de passe (/api/user/change-password, PATCH)
  — il te demande l'ancien mot de passe + le nouveau (min. 8 caractères).

  Les identifiants d'un autre utilisateur (ex. un agent terrain) :
  - Changer son email de connexion : fiche du gestionnaire ou de membre → bouton « Modifier »
    → /dashboard/admin/gestionnaires ou membres/[id]/edit, champ « Email de connexion ».
    Il y a aussi une case « Connexion Google uniquement » qui désactive
    complètement le mot de passe du compte (connexion via Google seulement).
  - Réinitialiser son mot de passe : page /dashboard/admin/superadmin →
    sélectionner l'utilisateur → action « Réinitialiser le mot de passe ». Ça
    génère un mot de passe temporaire affiché à l'écran (à lui transmettre
    toi-même) ; le compte est marqué mustChangePassword, donc il devra le
    changer à sa prochaine connexion. Un ADMIN peut le faire pour n'importe qui
    sauf un SUPER_ADMIN ; seul un SUPER_ADMIN peut réinitialiser un autre
    SUPER_ADMIN.
